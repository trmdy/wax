## Capability 1: `sheetSizeInfos` (the gate for the whole feature)

Advertised additively in `caps` on `version` and `open` JSON responses —
never on the `--version` line (release-workflow contract). No proto bump.

When advertised, **every** `open`/`meta` `sheets[]` entry always carries
all four size fields, folded flat into the entry (no nested defaults
object):

| Field | Type | Semantics |
| --- | --- | --- |
| `colInfos` | `[{c, width}]` | Zero-based column, width in Excel character units. Explicit custom widths only (`customWidth`-equivalent), same semantics as the dump field that predates this contract. |
| `rowInfos` | `[{r, height}]` | Zero-based row, height in points. **Amendment C:** an entry means "the file declares a height for this row" — for xlsx that is any `ht` attribute, whether user-set (`customHeight`) or an Excel-persisted autofit height, because both are the rendered height. Legacy containers use the equivalent rule (manually-sized flag, or a recorded height differing from the sheet default). |
| `defaultRowHeight` | number | Points. Always concrete. |
| `defaultColWidth` | number | Character units. Always concrete. |

**Amendment B (no absent-field ambiguity):** with the cap advertised, the
arrays are always present (possibly empty) and the defaults are always
concrete numbers — container declarations when present, otherwise the
Excel fallbacks **15.0 points / 8.43 characters**, resolved on the wire so
consumers never carry their own fallback. A declared `baseColWidth`
without `defaultColWidth` converts with the standard padding at the
default MDW of 7 (`base + 5/7`).

**Amendment E (container coverage):** xlsx coverage is guaranteed. xls and
xlsb are covered via wax's own BIFF/BrtRecord supplements (`Row`/
`DefaultRowHeight`/`DefColWidth`/`Standardwidth`/`ColInfo` and
`BrtRowHdr`/`BrtWsFmtInfo`/`BrtColInfo` with `fUserSet`), validated
against soffice conversions of corpus files. Other containers (ods, csv)
report empty arrays plus the fallback defaults.

The dump (`wax dump`, schema 1) gains the same three sheet fields
additively: `rowInfos`, `defaultRowHeight`, `defaultColWidth` (absent when
empty/undeclared, so earlier dumps stay byte-identical). Sparse-entry
counts are bounded by the used extent plus a 256-row/column headroom,
mirroring the pre-existing column rail.

## Size round-trip (writer fidelity)

Exports carry sizes through **exactly**: per-row heights, per-column
widths, `defaultRowHeight`, and `defaultColWidth` all survive a
read→write→read loop bit-for-bit. (Implementation note: rust_xlsxwriter
quantizes sizes to whole pixels and cannot write `defaultColWidth`; the
writer's XML normalization pass patches the exact values back in and
strips the per-row default-height stamps that would otherwise turn sparse
`rowInfos` dense.) Out-of-range sizes clamp loudly: heights to
`0..=409.5` points, widths to `0..=255` characters, each with a `dropped`
entry. csv exports list `"row heights"` alongside `"column widths"` in
their standing drop list.

## Capability 2: `exportSizeOverrides` (independent gate, best-effort ask)

`export` gains an optional
`sizeOverrides: {cols: [{sheet, c, width}], rows: [{sheet, r, height}]}`
(zero-based indices, character units / points):

- Entries collapse **last-wins** per column/row and layer over the read
  model's declared sizes before the clamp rail; overridden sizes travel
  through the exact-fidelity patch pass like declared ones.
- Taxonomy (A5 precedent): a malformed entry is `bad_request` naming the
  field (`sizeOverrides.cols[3].width must be a finite number`); an
  unknown sheet index is `bad_request`; the **combined** cols+rows count
  shares the 100,000-entry cap with cell overrides (`bad_request` naming
  the cap); a target beyond the xlsx grid (row ≥ 1,048,576, column ≥
  16,384) is `bad_request` naming the limit. Size overrides never grow
  the cell extent, so no bomb rail applies.
- Out-of-range values are **clamped loudly**, not rejected (the writer's
  standing clamp semantics).
- `format:"csv"` cannot represent sizes: overrides aimed at the exported
  sheet degrade **loudly** with a counted dropped entry
  (`"size overrides are not representable in csv (N)"`, post-collapse
  count); entries for other valid sheets are validated but silently out
  of scope (A6 precedent). Never `bad_request`, never silent.
- `applied` continues to count cell overrides only.

Nothing on the apiary side gates on this capability; it shipped because
it was cheap while the writer was open.

## Version pairing

First shipped in wax v0.3.0 (`wax 0.3.0 (proto 0)`). The `--version` line
