# W1 interface contracts (frozen by the coordinator)

These are the seams between the five W1 shards. They exist so shards run
**concurrently** instead of in a dependency chain. A shard may not change a
contract unilaterally: propose the change to the coordinator (buz/seal), the
coordinator amends this file on `main`, and affected shards rebase.

Everything here is W1-scope. Later waves are free to evolve these formats —
the harness contract in particular is expected to grow (window latency, fuzz
counters). Where W1 cannot produce a number honestly, it emits `null` and the
scoreboard prints `n/a`. **Never fabricate a metric.**

## 1. The normalized dump (the comparison currency)

Both the oracle (SheetJS) and `wax dump` emit **the same schema**, so the
comparator diffs like for like. One JSON document per input file, written to
stdout, UTF-8, no trailing newline requirement.

```jsonc
{
  "schema": 1,
  "tool": "wax" | "sheetjs",
  "toolVersion": "0.1.0",         // wax semver, or SheetJS version
  "file": "corpus/files/sheetjs/foo.xlsx",  // repo-relative when possible
  "sha256": "…",                  // of the input file
  "ok": true,
  "error": null,                  // {"code":"…","msg":"…"} when ok:false
  "wallMs": 1234,                 // parse wall time, this file only
  "peakRssBytes": 123456789,      // whole-process peak; null if unavailable
  "truncated": false,             // true if the cell cap was hit anywhere
  "sheets": [
    {
      "name": "Costs",
      "index": 0,
      "rows": 195114,             // 1-based extent (0 = empty sheet)
      "cols": 12,
      "truncated": false,
      "merges": ["A1:B2"],        // A1-style, ascending
      "cells": [ /* see below */ ]
    }
  ],
  "warnings": ["charts ignored (2)"]
}
```

### Cells

Sparse: **only non-empty cells**, ascending row-major by `(r, c)`, both
0-based. One object per cell:

```jsonc
{
  "r": 0, "c": 0,
  "t": "n",            // n number | s text | b bool | e error | d date
  "v": 12410.5,        // n:number  s:string  b:bool  e:string("#DIV/0!")  d:ISO-8601 string
  "d": "12 410,50 kr", // display string as the app would show it; null if unknown
  "f": "SUM(A1:A9)",   // formula text WITHOUT leading '='; null if not a formula
  "fmt": "#,##0.00 kr" // number-format code; null if unknown/General
}
```

Rules, binding on both sides:

- A formula cell carries **both** `f` and its cached result in `v`/`t`. If the
  cached result is absent in the file, `v` is `null` and `t` is the cell's
  declared type or `"s"`.
- Dates: `t:"d"`, `v` = ISO-8601 (`2026-07-27` or `2026-07-27T13:45:00`), epoch
  (1900/1904) already resolved. A serial number the tool could not confidently
  resolve to a date stays `t:"n"` — do not guess.
- `d` is the **display string**. The oracle uses SheetJS's `w`. W1's stub
  reader has no formatter, so wax emits `null` here for every cell; the
  scoreboard will show ~0% display coverage in W1. That is the correct,
  honest W1 number.
- Absent information is `null`, never `""` and never omitted.

### Cell cap

Both tools accept `--max-cells <N>` (default **200000**, per file, summed
across sheets). On hitting it: stop emitting cells, set `truncated: true` on
the sheet and the document, keep `rows`/`cols` at the true extent. Both sides
run with the same `N` so truncation is symmetric.

## 2. CLI surface (W1A → everyone)

```
wax --version                 # "wax <semver> (proto <N>)" on stdout, exit 0
wax dump --json <file> [--max-cells N] [--timeout-ms N]
```

- `dump` writes one normalized-dump document to **stdout**, diagnostics to
  **stderr**.
- Exit 0 when a document was produced — *including* `ok:false` documents. A
  file wax cannot read is a data point, not a harness crash. Reserve non-zero
  exits for usage errors (exit 2) and genuine aborts (exit 1, nothing on
  stdout).
- The harness locates the binary via `$WAX_BIN`, falling back to
  `target/release/wax`.

## 3. Stub reader (W1A)

W1's reader is deliberately partial and clearly labelled. It exists so the
harness has something real to score. Scope:

- xlsx (zip) only. Sheet names + order from `xl/workbook.xml`, extents from
  each sheet's `<dimension>` (else computed from seen cells).
- Emits **numeric cells and inline strings only**. No shared-string table, no
  number formats, no dates, no formulas' cached-result plumbing beyond what
  sits inline. `d` and `fmt` are always `null`.
- Non-xlsx input (xls/xlsb/ods/csv) → `ok:false`, `code:"unsupported"`.
- Every dump carries `"warnings": ["stub reader: text via shared strings,
  formats, and dates are not implemented (W2)"]`.

W2 replaces this with calamine. Do not invest in making the stub good.

## 4. Corpus manifest (W1B → W1C, W1D)

`corpus/manifest.jsonl`, one object per line, sorted by `id`:

```jsonc
{
  "id": "sheetjs/test_files/AutoFilter.xlsx",   // stable, collection-prefixed
  "path": "corpus/files/sheetjs/test_files/AutoFilter.xlsx",
  "sha256": "…",
  "bytes": 12345,
  "ext": "xlsx",
  "collection": "sheetjs-test-files",
  "source": "https://github.com/SheetJS/test_files/raw/…",
  "licence": "Apache-2.0",
  "fetchedAt": "2026-07-27T20:00:00Z",
  "private": false        // true = never redistribute, never commit, local-only
}
```

`corpus/manifest-summary.json` accompanies it: total count, count and total
bytes per collection, per-extension histogram, generation timestamp.

**Privacy rail:** the 16 spike files are real personal/business accounting
data. They are `private: true`, live outside `corpus/files/`, and must never
be uploaded, committed, or included in any published artifact. The manifest
references them by absolute local path so the harness can use them on this
machine and silently skip them anywhere else.

## 5. Oracle runner (W1C → W1D)

```
node harness/oracle/run.js <file> [--max-cells N] [--timeout-ms N]
```

One **fresh node process per file** (memory measurement is meaningless
otherwise). Writes a normalized-dump document with `tool:"sheetjs"` to
stdout. Same exit-code discipline as §2: a file SheetJS cannot read is an
`ok:false` document on stdout with exit 0. Crash/OOM/timeout is the harness's
problem to record, not the runner's to hide.

SheetJS is pinned as the CDN tarball, exactly as the spike did it:
`https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz`, integrity recorded in
the lockfile. Never depend on the stale npm `xlsx` package name.

## 6. Scoreboard (W1D)

`harness/run.sh [--manifest <path>] [--limit N] [--jobs N]` runs the corpus
end-to-end and regenerates `SCOREBOARD.md` plus a machine-readable
`harness/scoreboard.json`. Columns, wax vs the SheetJS baseline:

| metric | definition |
| --- | --- |
| files opened % | `ok:true` documents / files attempted |
| cell-value match % | over cells present in *either* dump, `(t, v)` equal (numbers within 1e-9 relative) |
| display-string coverage % | cells with non-null `d` / cells emitted |
| formula fidelity % | cells where `f` matches (whitespace-normalized) |
| cached-result fidelity % | over formula cells, `(t, v)` equal |
| p50 / p95 parse time | from `wallMs` |
| peak RSS | p50 / max of `peakRssBytes` |
| window latency | **n/a in W1** — no protocol yet; print `n/a`, do not fake |

Per-file results land in `harness/results.jsonl`. Files where wax and SheetJS
disagree and SheetJS is judged wrong get an entry in
`harness/adjudications.md` with a verdict and reasoning — **disagreements are
never auto-resolved in SheetJS's favour**.

## 7. Ground rules for every W1 shard

1. Stay in your lane: touch only the paths your brief assigns. Cross-shard
   edits need coordinator sign-off first.
2. Tests for logic, `cargo fmt` and `cargo clippy -D warnings` clean, node
   code lint-clean.
3. Corpus fetching is polite: rate-limited, resumable, identifies itself, and
   logs provenance for every byte. Public/test files only.
4. Nothing in this mission touches the apiary repo.
5. Seal with deliverables, test counts, and deviations. Blockers surface as a
   seal or a buz to the coordinator — never a silent stall.
